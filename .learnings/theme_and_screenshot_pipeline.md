# 嵌入式双主题调色板与串口自动化截屏验证最佳实践

## 1. I4 4-bit 硬件调色板双主题切换机制
- **零显存额外开销的双主题方案**：在 LVGL I4 格式下，显存仅存储 4-bit 调色板索引（0~15）。
- **清屏色彩对应**：`memset(buffer, 0, ...)` 会将整个画布填充索引 0。因此，将 Light Mode 调色板索引 0 设定为象牙暖白 (`0xFBF9F5`)，Dark Mode 索引 0 设定为极简黑曜 (`0x121315`)，无需在切主题时重构 UI 树，仅需 `lv_canvas_set_palette` 与重绘即可实现硬件级瞬时生效。
- **色彩语义宏封装**：在 C 代码中抽象 `COL_BG`, `COL_INK`, `COL_DIM`, `COL_CARD_BG`, `COL_CARD_BORDER`, `COL_ORANGE` 宏，保证业务界面代码无需硬编码十六进制色值，完全自适应当前主题。

## 2. 嵌入式汉字字库限制与命名避坑
- **字库精简限制**：固件内置的 `simhei` 裁剪字库（`buddy_font_zh_16.c`）只包含高频汉字集合。
- **字库查证原则**：增加或更改菜单选项文字时，严禁猜测，必须优先在 `.c` 字库源文件中匹配 Unicode 码点。
- **实证示例**：“暖”与“曜”字在精简字库中缺失，会导致文本显示被截断为单字“白”或乱码；改用字库中确认存在的“白色”与“黑色”（或“亮色”/“暗色”），既直观大方，又能 100% 稳定呈现。

## 3. 串口自动化测试与截屏流水线
- **休眠与截屏联锁**：固件具备 60 秒无操作休眠机制。自动化脚本抓取截屏时若耗时较长（115200 波特率下全屏 RGB565 需要 13 秒），可能在后续步骤触发自动休眠导致渲染停止。
- **防御措施**：在串口接收到任何测试指令（或截屏请求）时，必须主动重置 `screen_off = false`、`last_user_activity_ms = now` 并唤醒背光；在写入截屏前主动触发一次渲染重绘，保证显存内容 100% 同步。
